# Plan B2: Wave 3 (the single-player systems from level 19 to 60)

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax. Save this
> file as `docs/superpowers/plans/2026-11-26-plan-b2-wave3.md`.

**Goal.** Build the single-player systems a player meets after Wave 2, in unlock order. Wave 3
first closes the Wave 2 follow-ups:

- the celestial merchant (store 7, level 19);
- the hero-trial cooldown rule;
- the two run-11 unanswered ids;
- an emulator probe of the arena and guild level-up guides that no run has fired yet.

Then it builds, in unlock order:

| Level | System |
|---|---|
| 45 | blessing |
| 46 | hero develop |
| 47 | demon onslaught |
| 49 | angel radiance |
| 52 | signet + master dungeon |
| 54 | breakthrough |
| 55 | rebirth |
| 57 | divine ruins and artifact |
| 60 | angel advance |

The client is the spec. Every number comes from a stock `.db` row or a cited Lua line. The source
inventory is `docs/protocol-coverage-2026-11-25.md`.

**Architecture.** It keeps the B1/Wave-1/Wave-2 contract
(`handlers(registry, settings, conn, cfg) -> {(svc, cmd): fn}`, `fill_required`, `Session.queue`).

- **Phase A is serial.** It touches the shared files and ends with A5, which lays every Phase B
  schema item, config lookup, prize category and client-message field.
- **Phase B is parallel in worktrees.** Each task owns one NEW module and its NEW test file. Only
  B5 also touches `level.py`. No Phase B task touches `hero.py`.
- **Each module that adds hero stats exposes `bonus(conn, cfg, hero_row) -> dict[str, float]`**,
  the same shape as `hero.gear_bonus`. Phase C sums the bonuses in `hero.py` once.
- **Phase C is serial:** wiring, then ACC-W3-2.

**Tech.** `py -3.14`, protobuf 7.36.2, pytest 9, stdlib sqlite3/asyncio, AVD `LOA_API30`. No
client (APK) change.

## Global constraints (house rules baked in)

- **Python and tests.** Python is always `py -3.14`. The test command is
  `py -3.14 -m pytest -q --basetemp=C:/tmp/pytest-loa-w3-<task>`: forward slashes, a **distinct
  basetemp per task and worktree**, never shared between parallel runs.
- **Branch.** **Never `git push`.** Work on the NEW branch `plan-b2-wave3`, cut from `master` HEAD
  when A1 starts. The brief says `02f70ab`, 800 tests; record the real suite count verbatim before
  the first commit. Make one local commit per task or numbered sub-commit, with messages like
  `feat(server): ...` ending in the session attribution line.
- **A parallel implementer** is committing small fixes on `master` in `guide.py`, `train.py`,
  `events.py`, `gacha.py` and `docs/TODO.md`. Before each Phase A task, merge or rebase on
  `master`. A Phase B task that finds it needs one of those files stops and reports.
- **Worktrees.** Parallel tasks run in git worktrees. In each one, junction `.stock` read-only
  with `cmd //c mklink /J .stock "<main-tree>\.stock"`. **Never `git stash`.**
- **Migrations.** `data/player.db` migrations are additive only: `CREATE TABLE IF NOT EXISTS` and
  `ADDED_COLUMNS` in `server/db.py`. Every `data/player.db.*` world must still open.
- **Config reads** go only through `server/config/`. **Never look up by `id` and never count with
  `count(*)`** (inventory warning). Key on data columns, e.g. `hero_breakthrough_level`, `level`,
  `star`. Cast stock TEXT columns.
- **Status codes** are the client's own `language.db` ids, quoted per handler. Never invent one.
  The relevant blocks:
  - 336001-336013 (神之遗迹)
  - 337001-337005 (神器)
  - 338001-338006 (护佑)
  - 338107-338117 (印记)
  - 338163-338164 (圣辉)
  - 339174 (突破)
  - 339175 (进阶)
  - plus the Wave 1/2 codes (327937 gold, 327938 diamond, 327942 items, 327957 level).
- **A Res without `status` cannot refuse** (TODO "Known client behaviour"). Such a handler changes
  nothing on a shortfall, logs a WARNING with the code it would have used, and answers the current
  state. In Wave 3 these are:
  - `HeroDevelopRes`/`HeroDevelopEnsureRes`
  - `MagicArmyBattleStartRes`
  - `AngelGloryUpgradeRes`
  - `SignetLevelUpRes`
  - `HeroBreakthroughRes`
  - `HeroTransmigrateRes`
  - the `God*Res` family
  - every `Artifact*Res`
  - the `AngelAdvance*Res` family
  - `BlessHeroAddRes`/`BlessFusingRes`/`BlessQuickAddUnitRes`/`BlessBuyLocationRes`.
  Each B task's step 1 confirms its list against the proto.
- Every response and queued notify goes through `fill_required`. Validate the whole cost and the
  whole prize list first, then write (the `item.grant_prizes` pattern).
- **Human-read dates** (logs, doc tables) are `dd-mm-yyyy`. Stored values are ISO or epoch.
  **Flatpickr and the responsive recipe: N/A** (no web UI).
- **One new shared helper only:** `config.parse_rate_ladder`, with two callers (B6 breakthrough,
  B10 angel advance). Everything else is per-module.
- **Missing schema.** A Phase B task whose step 1 shows a needed column or table that A5 did not
  lay **stops and reports**. The fix is a serial A5b, never an edit to `db.py` in a worktree.

## Risks

1. **A1 may find a wedge.** The arena or a guild guide may lock the city at 15/30/40. Then a
   multiplayer stub becomes a single-player blocker, and A1b (O-W3-2) moves ahead of Phase B.
2. **O-W3-5 and O-W3-8 are readings of table numbers, not client code.** The develop roll and the
   breakthrough/advance success rule could feel different from the original. Each rule is one
   function with injectable `rng`, so the owner can retune it without touching the protocol.
3. **The `count(*)`/`id` trap.** Any lookup on `id` in `hero_breakthrough_info`, a signet table or
   artifact tables silently returns nothing. A5's tests pin the data-column lookups. Reviewers
   grep for `"id"` in new config methods.
4. **Signet attributes (O-W3-7)** are the least specified piece. If step 1 finds a client-side
   rule that disagrees with stored rolls, attributes already stored on copies are wrong. Only
   throwaway copies hold signets before ACC.
5. **Stats feeding the fight.** Six bonus sources enter `unit` in C1. A double count would make
   heroes too strong, which is the reverse of 10022. `test_wave2_unit_unchanged_without_wave3_rows`
   pins the baseline.
6. **Rebirth may need a hero-cap change** in `train.py`/`level.py`, both outside B7's files. B7
   stops and reports rather than editing them.
7. **The parallel implementer on `master`.** `herotrial.py` (A2) and `mystery.py`/`shop.py` (A3)
   are not in their list, but `train.py` is (B7 risk 6). Merge `master` before each Phase A task.
8. **Divine ruins and artifact are the largest unknowns.** They are split into five commits and
   can ship last without blocking B1-B7 or B10.
9. **Prize categories.** Any drop category beyond {1, 2, 9, 11, 20, 21, 30, 40, 51, 52, 75, 86}
   raises in `grant_prizes`. A5's scan test covers the stage drops. B-task tests roll their own
   prize ids.
